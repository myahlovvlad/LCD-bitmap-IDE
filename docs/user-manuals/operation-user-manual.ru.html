LCD-bitmap IDE

Настольная среда для проектирования монохромных LCD-интерфейсов встраиваемых устройств: экраны, конечный автомат навигации, физическая панель, runtime-теги и firmware-ready экспорт — в одном файле проекта.

Глава 1

Первый запуск

Приложение не требует установки зависимостей и не обращается в сеть: весь проект — это один файл .lcdproj.

  1. Установите сборку под вашу ОС со страницы GitHub Releases, либо запустите исходники командой npm run electron:dev.
  2. На стартовом экране выберите язык интерфейса и один из четырёх путей: открыть существующий .lcdproj, создать новый проект, восстановить автосохранение или открыть встроенный демо-проект.
  3. Для первого знакомства выбирайте Demo — он уже содержит связанные состояния, экраны и переходы, на которых можно учиться, ничем не рискуя.

Проект автосохраняется в localStorage каждые несколько секунд. Это подстраховка на случай сбоя, а не замена явному Save project — сохраняйте файл на диск вручную перед закрытием сессии.

Глава 2

Устройство интерфейса

Слева — компактный навигатор рабочих областей, сгруппированных по смыслу: Interface (экраны и панель), Logic (FSM и аварии), Hardware (теги и процедуры), Verify & deliver (симуляция и передача прошивке). Каждая рабочая область имеет собственные независимо сворачиваемые боковые панели.

  • Кнопка Collapse navigator (или Ctrl+B) сворачивает только глобальный навигатор в узкую иконочную полосу — боковые панели конкретной рабочей области при этом остаются на месте.
  • Строка состояния внизу всегда показывает размер дисплея, число состояний/переходов FSM, число экранов и элементов панели, а также статус валидации и наличие несохранённых изменений.
  • Переключатель темы (Settings → Theme) поддерживает светлую, тёмную и системную схему.

Глава 3

Редактор FSM

Конечный автомат — это карта навигации устройства: состояние соответствует одному LCD-экрану, переход — реакции на кнопку, таймер или условие.

Режим редактирования

Граф по умолчанию открывается только для чтения — это намеренная защита от случайного изменения рабочей логики. Кнопки, изменяющие граф (добавление состояния, удаление, перетаскивание), становятся активны только после явного включения Edit graph.

Создание состояния и перехода

  1. Включите Edit graph, затем нажмите + над списком состояний либо кликните правой кнопкой по пустому месту холста → Add state.
  2. Назовите состояние и при необходимости отметьте его как Initial (точка входа) или Terminal (конечное).
  3. Для перехода между состояниями либо перетащите связь между точками соединения на узлах, либо используйте раздел Transition routes в инспекторе справа — выберите целевое состояние и событие, не работая с холстом напрямую.
  4. Свяжите состояние с LCD-экраном через Linked LCD screen → Edit layout, чтобы сразу перейти к его пиксельному дизайну.

Обзор и фильтры

При большом графе включите Overview — он показывает по одному входу на каждую подсистему вместо полного графа. Если из-за обзора, фокуса на подсистеме или фильтра слоёв часть переходов скрыта, панель инструментов показывает счётчик «показано / всего» и причину — рядом всегда доступна кнопка сброса фильтров в один клик.

Глава 4

Редактор LCD-экранов

Каждый экран — это точный по пикселям монохромный framebuffer заданного размера (обычно 128×64), редактируемый как холст с типизированными объектами: текст, линии, прямоугольники, битовые изображения, спецэлементы.

  • Select / Add text / Line / Rectangle / Invert row / Special element / Glyph editor — основной набор инструментов рисования; каждый объект остаётся редактируемым (не растеризуется) до экспорта.
  • Pixel editor становится доступен для выбранного bitmap-объекта — точечное редактирование конкретных пикселей.
  • Каждый экран можно привязать сразу к нескольким состояниям FSM и слою (например, «Демо» или пользовательский слой) через панель Linked FSM states справа.

Глава 5

Импорт растра

Готовую графику (логотип, иконку, скан) можно превратить в 1bpp-изображение и продолжить редактировать её попиксельно как обычный bitmap-слой.

  1. Откройте экран, на который нужно поместить изображение, и перейдите на вкладку Import image.
  2. Выберите файл, настройте Threshold (порог бинаризации) и Dithering, пока превью 128×64 не станет читаемым.
  3. Нажмите Insert and edit bitmap — изображение сразу вставится на экран, выделится и откроется в пиксельном редакторе для точечной доработки.

Глава 6

Анимации

Ресурс анимации — это упорядоченный набор 1bpp-кадров с длительностью каждого кадра и флагом зацикливания. Один ресурс можно привязать целиком к экрану или только к одному bitmap-слою, оставив остальной экран статичным.

  1. Нажмите New animation и выберите изображение для первого кадра — по размеру выбранного bitmap-объекта, либо по размеру экрана, если объект не выбран.
  2. Добавляйте следующие кадры из других изображений, настраивайте длительность каждого в миллисекундах, дублируйте, удаляйте и переупорядочивайте их.
  3. Включите Loop для повторяющейся анимации (например, индикатор ожидания) или оставьте выключенным для одноразовой последовательности.
  4. Просмотрите результат через play / replay / ползунок на детерминированных часах, затем привяжите ресурс кнопкой Bind to screen (весь экран) или Bind to selected layer (только выбранный bitmap-объект).

Для меняющихся числовых значений (например, обратный отсчёт таймера) используйте текстовое поле с runtime-тегом, а не анимацию: анимация предназначена для графики, а не для сотен почти одинаковых кадров с цифрами.

При экспорте прошивки каждый ресурс превращается в массив кадров lcd_animation_frame_t (байты, их количество, длительность) и обёртку lcd_animation_t (таблица кадров, их число, флаг loop) — метаданные привязки к экранам и слоям экспортируются вместе с ними.

Глава 7

Панель управления

Физическая раскладка кнопок и индикаторов проектируется отдельно от логики и связывается с событиями FSM.

  • Group / Ungroup и инструменты выравнивания — для аккуратной раскладки множества элементов.
  • Grid и Snap обеспечивают точное позиционирование по сетке в пикселях корпуса.
  • Панель Panel validation справа снизу сразу показывает, есть ли кнопки без привязанного события.

Глава 8

HMI Designer

Объединяет экран и физическую панель в одну сцену для проверки сценария взаимодействия целиком: какая кнопка что делает на каком экране, какие теги и процедуры задействованы.

Режим Coverage помогает найти состояния или элементы панели, ни разу не задействованные ни в одном сценарии — полезно перед передачей прошивке.

Глава 9

Теги, процедуры, аварии

Три связанных реестра описывают то, что физически происходит на приборе, но не рисуется на экране напрямую.

РазделНазначениеГде
Tag registryТипизированные данные прошивки (float / int / bool / string), которыми обмениваются экраны и процедурыHardware → Tag registry
ProceduresИменованные backend-процессы (например, калибровка), документируемые инженерными заметкамиHardware → Procedures
AlarmsИменованные события аварийного состояния, проверяемые из любого перехода FSM независимо от текущего экранаLogic → Alarms

Глава 10

Runtime-предпросмотр

Прогон логики FSM без прошивки: нажимайте виртуальные кнопки, смотрите на живой рендер LCD-экрана и журнал событий — прежде чем передавать проект встраиваемой команде.

  • Step mode выполняет переходы по одному событию за раз — удобно для разбора сложной логики.
  • Express timer ускоряет симулированные таймеры, не меняя логику переходов.
  • Bypass procedures позволяет пропустить внешние backend-процедуры при прогоне сценария целиком.
  • Панель Validation слева выводит те же предупреждения, что видит валидатор проекта — например, недостижимые состояния.

Глава 11

Передача прошивке

Финальный шаг перед выпуском — сборка пакета для встраиваемой команды: валидация, пакет для поставщика, проверка соединения с устройством.

Важно: этот пакет — спецификация HMI/FSM, а не бинарник прошивки. Он передаёт поставщику экраны, привязки, переходы состояний, текстовые ресурсы и байты дисплея с трассируемостью. Исходники C/C++, детали MCU и тулчейна, драйверы и протоколы, процедура обновления устройства — по-прежнему задача встраиваемой команды.

Глава 12

API и MCP-серверы

Electron- и Tauri-сборки запускают одинаковый локальный контракт автоматизации: REST на 127.0.0.1:8766 и MCP (JSON-RPC/HTTP) на 127.0.0.1:8767/mcp — это позволяет внешним скриптам, SCADA-системам и LLM-агентам читать и редактировать открытый проект напрямую.

  • Оба сервера привязаны только к 127.0.0.1 и никогда не слушают внешний интерфейс.
  • GET /health на MCP-порту — проверка доступности без токена и без доступа к проекту.
  • Переменная окружения LCD_IDE_AUTOMATION_TOKEN включает обязательную Bearer-авторизацию для операций записи.
  • Полный список инструментов, схемы и примеры интеграции — в docs/API_MCP_CONNECTORS.md.
