# С чего начать

LCD-bitmap IDE описывает интерфейс встраиваемого устройства как один связный
проект. Не пытайтесь сразу изучить все рабочие области. Сначала задайте сценарий
работы устройства, затем последовательно добавляйте детали.

## Короткая ментальная модель

```text
Проект
  ├─ Поведение: события → состояния FSM → переходы
  ├─ Представление: LCD-экраны → объекты → тексты и bitmap-ресурсы
  ├─ Управление: физические кнопки → события
  ├─ Данные и действия: теги → процедуры → аварии
  ├─ Проверка: симуляция Runtime
  └─ Передача: Handoff-пакет и экспорт для прошивки
```

FSM отвечает на вопрос **«что сейчас делает устройство?»**. Экран — **«что
видит оператор?»**. Привязка кнопки — **«какое событие отправляет оператор?»**.
Теги, процедуры и аварии связывают интерфейс с данными и действиями устройства.
Runtime проверяет общую модель, а не хранит вторую копию проекта.

## Первый учебный проект

1. Откройте **Demo** и один раз пройдите встроенный **Tour**.
2. В **FSM** создайте минимальный маршрут: начальное состояние, одно действие,
   результат или ошибка.
3. В **LCD** назначьте и нарисуйте экран для каждого состояния, которому нужен
   собственный вид.
4. В **Control panel** привяжите кнопки к уже созданным событиям FSM.
5. Добавляйте **Tags**, **Procedures** и **Alarms**, только когда нужны живые
   значения, команды устройства или обработка ошибок.
6. В **Runtime** пройдите штатный сценарий, отмену и хотя бы один путь ошибки.
7. Сохраните `.lcdproj`, затем подготовьте **Handoff** или экспорт для прошивки.

**Screen DSL**, **Text registry**, API/MCP и расширенные настройки нужны после
того, как минимальный проект успешно проходит Runtime. Это дополнительные
способы редактирования и интеграции, а не отдельные модели проекта.

## Правила мышления

- Сначала создавайте событие, затем используйте его в переходах и кнопках.
- После интеграции сохраняйте стабильными ID состояний, экранов, событий и тегов.
- Переиспользуйте экран только тогда, когда состояния действительно показывают
  оператору один и тот же вид.
- Источник истины — предметная модель внутри `.lcdproj`. DSL-документы,
  compiler IR, состояние Runtime, выделение и масштаб — производные или
  временные данные.
- Устраняйте ошибки валидации до экспорта. Проверяйте ошибки, отмену и
  восстановление, а не только успешный путь.
- Не помещайте JavaScript в условия: среда выполнения намеренно использует
  ограниченную декларативную модель.
